# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is Prism?

Prism is a universal interface for documents, messages, tasks, calendar, and knowledge management, backed by a Parachute vault (SQLite knowledge graph at localhost:1940). It ships in three shells over one shared React 19 UI core:

- **Desktop** (`apps/desktop`) — **LEGACY since WP4.3: kept building as the rollback path only; Prism Client replaces it on every Mac (`apps/desktop/README.md`, parity table `docs/roadmap/architecture-v2/desktop-parity.md`).** Tauri 2.x (Rust backend + React frontend). The host-mode app that holds a vault token; talks to Parachute (and Matrix/Google/Claude/Notion) directly.
- **Web** (`apps/web`) — a static PWA (mobile + desktop browser) for editing the vault from anywhere and **Google-Docs-style sharing**. The browser holds **no vault credentials**; it talks only to the **Prism Server** gateway.
- **Client** (`apps/client`, Arch v2 WP4.1) — "Prism Client", a thin Tauri 2 shell bundling the **native** web build (`apps/web/dist-native`). It signs in via system-browser PKCE with a loopback redirect, keeps the `pd_…` device token in the Keychain, and talks to ONE configured Prism Server. There is no vault token, no ingest and no CLI spawning, and it exposes just 8 IPC commands to the main window (+1 to the separate quick-capture window, WP4.2: tray + global-shortcut quick capture, notifications, export, drag-drop; see docs/client-app.md "Native extras"). It installs side by side with the legacy desktop (`com.benjaminlife.prism.client`). iOS joins this shell in WP5. **Gotcha:** it is Tauri, but `isDesktop` (`packages/core/src/lib/platform.ts`) is false there because `window.__PRISM_HOST__` is present — keep that check if you touch shell detection. Its CSP allows only the server for connect/img (page script can read the bearer); external note images and the OpenFreeMap basemap therefore come through the server's SSRF-guarded proxies (Client parity C, below) — never widen the client CSP for them. Docs: `docs/client-app.md`.

### Monorepo layout (npm workspaces)

```
packages/core         Shared React UI: renderers, editor, layout, stores, VaultClient seam
apps/desktop          LEGACY Tauri host-mode shell (rollback only since WP4.3; src-tauri lives here)

apps/server           Prism Server — Node home-server: auth + permission gateway + (P3) collab

```

**VaultClient seam** (`packages/core/src/data/`): the UI core depends on a `VaultClient` interface, dependency-injected per shell — `TauriVaultClient` (invoke) for desktop, `HttpVaultClient` (fetch → gateway) for web. One UI, two transports.

```
├── components/renderers/       ← invoke() →      ├── commands/        (IPC handlers)
├── components/layout/                             ├── clients/         (HTTP: parachute, matrix, google, claude, ollama)
├── app/stores/ (Zustand)                          ├── services/        (background tokio tasks)

└── lib/dashboard/ (filter engine)                 └── models/          (Rust data types)
```

### Key Principles

1. **Parachute owns the data.** Never touch SQLite directly. All reads/writes go via HTTP API at localhost:1940.
2. **Tags are the type system.** Notes are typed by tags (`task`, `meeting`, `person`, `project`, etc.), not `metadata.type`. The `inferContentType()` function in `src/lib/schemas/content-types.ts` maps tags → `ContentType` → renderer.
3. **Frontend talks only to Rust.** All external API calls (Matrix, Google, Claude, Notion) happen in Rust commands. Frontend calls `invoke()` only.
4. **Agent uses Claude Code CLI — hardened.** The `ClaudeClient` and `DispatchManager` spawn `claude -p` subprocesses (not the Anthropic HTTP API), and EVERY desktop spawn is built by `src-tauri/src/clients/claude_args.rs` (WP0.1d, mirrors the server runner): no built-in tools, ONLY the active vault's MCP via a per-run 0600 config, an explicit per-feature vault-tool allowlist under `dontAsk`, no settings sources, a fixed EMPTY cwd under the app-data dir (NOT the repo root), env allowlist. Never hand-build a claude argv or re-add `--dangerously-skip-permissions`. See *Desktop agent runner* below.
5. **Tauri commands return `Result<T, PrismError>`.** `PrismError` serializes to a string for the frontend. All new commands must follow this pattern.

## Prism Server & Web Sharing (the security gateway)

`apps/server` is a Node home-server (Hono + better-sqlite3) that is the **single trust boundary** for the web/shared path. It is the **only** component that holds the vault token; clients never get one.

```
Browser ── session cookie OR capability link ──▶ PRISM SERVER (apps/server) ── vault token ──▶ Parachute
          (httpOnly, no token in JS)              ├ /auth/*  magic-link sign-in, sessions, logout, me
                                                   ├ /api/*   permission gateway (authorize every read/write)
                                                   └ /*       serves the built web PWA (same-origin)
```

**Auth (`src/auth/`).** Three actor kinds resolved per request (`actor.ts`): a signed-in **user** (httpOnly session cookie → SQLite row, `session.ts`; or a native **device token** `Bearer pd_…`, see below), an **anyone-with-link capability** (HMAC-signed token naming a grant id, `capability.ts`), or **anon**. Auth is **invite-only with passwords** — there is no open self-signup:
- **Owner** (`OWNER_EMAIL`) signs in via **magic link**, which is **owner-only** (gated at both `/auth/request` and `/auth/callback`) — bootstrap/recovery, since the owner controls that inbox.
- **Everyone else**: the owner issues an **invite** (`invite.ts` — single-use, hashed, 7-day) → recipient **registers** a password account (`password.ts` — scrypt) at `/accept-invite?token=` → logs in with email + password (`/auth/login`). Sharing by email (`/acl` people endpoints) auto-invites, so a grant binds to a real authenticated account, not a bare email. Generic 401s avoid account enumeration; `/auth/login` + `/auth/register` are rate-limited.
- Email via **Resend** (`RESEND_API_KEY`, shared sender in `email.ts`); with no key, links log to the console (dev only). A signed-in **non-owner with no grants sees nothing** (empty `/api/notes`, 403 on notes + the graph) — authentication never implies authorization.
- **Native clients: device tokens (WP2.1, `auth/device.ts` + `routes/device.ts`, full spec `docs/native-auth.md`).** RFC 8252 + PKCE S256 (plain refused): the app opens `/auth/device/authorize` in the system browser. `redirect_uri` must exactly match `DEVICE_REDIRECT_URIS` (default `prism://auth/callback`) or be a loopback `http://127.0.0.1|[::1]:<port ≥1024>/callback` (or `/`) with no query. EVERY pre-consent error gets a 400 page, never a redirect. The params are parked server-side (`device_auth_requests` + an httpOnly `prism_device_req` cookie). A signed-out browser goes to `/?next=/auth/device/continue`. `postLoginTarget()` honors ONLY that exact path, and `/auth/callback` resumes it after a magic link. The consent POST is bound to the session, a CSRF HMAC, and the parking cookie. Then `/auth/device/token` exchanges code + verifier (5-min single-use code; a replay revokes the minted token; rate-limited) for `pd_…`. Only its SHA-256 is stored (`device_tokens`); it has a 90-day sliding expiry with a 365-day cap. `resolveActor` checks `Bearer pd_…` right after the session cookie and yields the SAME user actor (role + grants). It is honored over the tunnel, unlike the loopback-only COLLAB_TOKEN branch, which is unchanged and never sees a `pd_` token. Collab `resolveLevel` accepts it as the Hocuspocus `token`. Tauri origins (`NATIVE_ORIGINS`) get **non-credentialed** CORS; the APP_ORIGIN cookie rule is untouched. Manage devices at `GET /auth/devices` and `DELETE /auth/devices/:id` (own only; the server owner may use `?all=1` and revoke any), shown as **Settings → Account → Signed-in devices** through the optional `AccountClient.listDevices/revokeDevice` seam. The consent page shows the label as a claim ("An app calling itself …") and the redirect target prominently. **Hardening:** `/auth/change-password` via a device token requires the current password and can NEVER set a first password (browser session only). A successful change revokes the account's OTHER devices. MCP tokens minted through a device (`mcp_tokens.device_id`) are revoked with it (`revokeDevice`, through the `mcp-token` revoker). Capability links made through a device persist, like a session's. `consentCsrf` throws without `SESSION_SECRET`.

**Permissions (`src/permissions.ts`).** Levels `view < comment < suggest < edit < own`. `effectiveLevel(grants, note, isOwner)` = max over grants matching the note **id** or any of its **tags**, with owner → `own`. Grants live in SQLite (`db.ts`): `(subject_type: user|link|anyone, subject, resource_type: note|tag|page|…, resource, level)`.

**Page-subtree grants (wave 2D, NP-CO-09).** `resource_type: "page"`, `resource` = a page's NOTE ID: matches that page and every note whose path is under the page's CURRENT path ("sharing a page shares its sub-pages"). The anchor's path is resolved synchronously from the tree projection (`tree.ts` registers `setPageAnchorResolver`; `warmPageAnchors(grants)` loads it before a decision — gateway middleware + collab `resolveLevel`); unknown/trashed anchor → matches the anchor id ONLY (fail closed). The grant follows the id: moving the shared page keeps its subtree shared, moving a sub-page out drops inherited access, a new page at the old path inherits nothing. Among page grants the NEAREST shared ancestor wins (that is how a child is restricted or expanded); note/tag/space/vault grants and the role floor still union. Never for private notes (except a page grant ON the private page = an explicit share). `NoteRef.path` is threaded through every `effectiveCaps` call site — a ref without `path` matches page grants by id only, so a NEW call site must pass it. ACL: `PUT /acl/notes/:id/people {scope:"page"|"note"}` (default = the person's existing kind; one grant per person per page), `DELETE` removes both kinds; a scoped (non-admin) sharer may make a page share only while holding the granted caps + `share` on every current sub-page (refusal names none); `GET /acl/notes/:id` adds `owner`, `people[].{name,avatar,scope}`, `inherited[]` (per person, nearest ancestor, with `from`), `parent`; canonical ids only. Names/avatars go only to callers who already see the access list (admins, `share` holders); the owner row's email to admins only (`src/sharing.ts` NAMING POLICY). **Moves and page shares (review C1/H1):** a non-owner PATCH may NOT change `path` (`organize` → 403 `move_required`; an editor's stray path is ignored) — every move goes through `POST /api/notes/:id/move` (the MCP `prism_update_note` path change too), which refuses, for non-admins, (a) landing a page that carries page grants over EXISTING notes and (b) landing the group under a page shared with others that does not already cover it, unless the mover holds `share` on every newly exposed note (generic refusal; admin bypass audited as `pages.move-share-bypass`). **Scoped sharers (M2)** cannot change/remove a grant made by an admin/owner/governance, replace another sharer's grant of the other kind, or lower anyone's current access on the page or its sub-pages (`scopedSharerRefusal`). `access-preview` 404s unless `parent` is a viewable page the caller can add to; only viewable ancestors count (M1). `GET /api/notes` for page grantees: ≤ `PAGE_GRANT_LISTINGS` (25) subtree listings, `PAGE_GRANT_LIST_PER_MINUTE` (30) per caller. **Re-review round 2.** *Nearest-wins consequences (L-6):* a page grant on a sub-page REPLACES what its holder inherits from above (it can restrict as well as expand) — so anything that puts a nearer anchor above notes is access-changing: the move route also refuses a non-admin move that would LOWER another person's page-inherited access on a note that still inherits (`lowers`; admin bypass audited), and a scoped sharer's new/changed grant may never leave the person with less than they have WITHOUT that sharer's own grants on the resource (they may freely lower/remove what THEY gave — also on `PUT/DELETE /acl/tags/:tag/people`, where a grant made by an admin/owner/governance or by anyone else is untouchable). *Trash (H-A/M-D):* a TRASHED anchor still resolves but reaches only notes that are in the Trash themselves (so whoever trashed a shared page can see and restore the group), live notes under its path inherit nothing; restore runs `restoreExposure` (live notes now under the restored paths need the restorer's `share`; admin bypass audited `pages.restore-share-bypass`); non-admin moves under a trashed page's path are refused. *Own-share growth (H-B):* moving a note under ANY newly covering page share needs `share` on it when others gain access OR the mover's own caps on it would grow. *Creates:* `createCapsAt(actor, path, tags)` (`sharing.ts`) = the caps for a NEW note at a path (page shares on ancestors count; empty under a trashed page) — the create handler's rule is `createCapsAt(...).has("create")`. *Identity (M-A/M-B/L-4):* a non-admin never receives an email from metadata — `writerNames(allowEmail)` yields emails only for admins; `/api/query` gives non-admins display names (or nothing) for writer AND creator and drops `prism_last_change`; `prism_creator` is removed from non-admin note responses in favour of `_creator {me, name}`; `/acl/notes/:id` `note.creator` is null for non-admins (`createdByMe` instead), `inherited[]`/`parent`/activity/access-preview count only ancestors the caller can VIEW and carry emails for admins only. *Listing (L-3):* `/api/notes` expands 25 outermost shared pages per request; more → `X-Prism-Truncated: shared-pages` + `X-Prism-Shared-Pages-Next: <offset>`, continue with `?shared_pages_offset=`. Tests: `test/page-grants.test.ts`, `test/sharing-security.test.ts`.

**Sharing reads (`routes/sharing.ts`, before the owner short-circuit, per-actor 60/min).** `GET /api/shared-with-me` (signed-in users; top-level note/page grants still viewable + tag grants; `sharedBy` = display name only), `GET /api/comments?note=&unresolved=1&mine=1&limit=` (threads from the live doc or SQLite snapshot of VIEWABLE pages only — no actor ids, `mine` computed server-side; ≤400 docs scanned), `GET /api/notes/:id/activity` (comments + shares (shares only for access managers) + `lastEditor`), `GET /api/notes/:id/access-preview?parent=` (who would lose/gain inherited access by a move; names only for access managers). **Writer attribution (server-owned, review M3):** the stamp is 2C's `writer-stamp.ts` (`prism_last_writer` = OPAQUE `u_<hmac>` id or `"link"`, `prism_last_write_at`) plus `prism_last_change` = `<kind>@<write_at>` (`sharing.ts` `writerStamp`/`changeKindOf`; kind `edit` | `suggestion` human command | `agent` Prism MCP | `accepted-suggestion` heuristic; a kind bound to an older stamp time is ignored). Stamped by collab stores (most recent writer; server-internal stores leave it alone) and gateway content writes (`agent` when `requestVia` is `mcp`). Client values for the three keys are DROPPED on non-owner PATCH/create (`/api/properties` refuses `prism_*`), and the keys are stripped from every non-owner note response (`forViewer`/`annotate` in api.ts; version rows also drop `prism_trashed_by`; links additionally `stripIdentity`). Non-owner version rows carry `writer: {kind,name,self}`; names resolve through `writerNames()` for SIGNED-IN viewers only (an account whose name is its email reads as unnamed to others). `GET /api/notes/:id/activity` adds `writers` (names of THIS page's stamps) + `me` so the owner passthrough's raw stamps resolve client-side (`@prism/core` `writerOf(input, directory)`, `usePageActivity`). Tests: `test/sharing-routes.test.ts`. Client: `components/sharing/*` (SharedWithMe, PresenceAvatars, PageInfo, PageUpdates, MoveAccessNotice, PersonAvatar), VaultClient optional `listSharedWithMe/listComments/getPageActivity/getAccessPreview`.

**2D ⇄ create-allowlist integration (merge of main 632abe9).** A non-owner path change stays `move_required` (PATCH never moves; main's `placementRefusal` block for PATCH is gone — main's tests now drive the same destinations through `POST /notes/:id/move`, where a trashed parent is 403 and a plain folder is the owner's). `destinationParentRefusal` (pages.ts, THE create/move placement hook) also counts standing AT THE PLACE: `createCapsAt(actor, target, [])` (page share on any ancestor, vault grant, role floor; empty under a trashed page) — tags are deliberately not passed, a tag grant is not standing inside a page. **Tree projection (`GET /api/tree`, `src/tree.ts`, WP7.1).** The file tree no longer lists the vault: the server holds a per-vault in-memory projection of `[{id, path, tags, updatedAt, type?, prismType?}]` (`type` = `metadata.type`, `prismType` = `metadata.prism_type` — the only two metadata keys `inferContentType`/ProjectTree read; creator/visibility are kept internally for the private-note rule but never emitted). Served to owners (vault chosen by `X-Prism-Vault`) AND non-owners (filtered per request through `capsFor(...).has("view")`, so no path/tag of an unviewable note leaks); registered BEFORE the owner short-circuit; gzip via `hono/compress`; `ETag` (weak, content hash) + `If-None-Match` → 304, `Cache-Control: private, no-cache`. **Freshness, three layers:** (1) the vault's live subscribe WebSocket (`/vault/<v>/api/subscribe?include_content=false`, first-message auth with the server's vault token) — its *snapshot is the build* (no separate REST list), `upsert`/`remove` frames keep it current for writes made anywhere; reconnect with backoff 2→60 s, each reconnect snapshot replaces the rows wholesale; (2) write-through from the gateway (owner passthrough via `treeAfterOwnerWrite`, non-owner create/patch/restore/delete) so the writer's next read is exact; older `updatedAt` never clobbers a newer row; (3) fallback: socket failing / no snapshot within `TREE_SNAPSHOT_TIMEOUT_MS` (60 s) → ONE lean list (`include_content=false&include_metadata=type,prism_type,prism_creator,prism_visibility`), plus a `TREE_REBUILD_MS` (5 min) periodic rebuild while the socket isn't live; broad changes (`/tags*` writes, batch verbs) debounce a rebuild. Built lazily on first request per vault (first load waits for the snapshot; later loads are memory). Env: `TREE_SUBSCRIBE=0` disables the socket (tests do), `PRISM_TREE_LOG=1` logs rows/build ms/served bytes. Web `rest.listTree` uses it (falls back to the legacy full list on an older server's 404/403) and the IDB read cache now caches it (under the 4 MB cap; ~2.4 MB raw / ~0.4 MB gzip at 14k notes, estimated). **Desktop still uses its Rust `vault_list_tree`** (it talks to the vault directly, no gateway).

**Invalidation channel (`GET /api/events`, `src/events.ts`, WP7.2, `docs/events.md`).** SSE, ids only: `{type:"note",id,op:"upsert"|"remove"}` / `{type:"resync"}`; `: ping` every 25 s. Owner/admin: all events for the vault chosen by `X-Prism-Vault`. Capability links: allowed, view-scoped the same way. Anon: 401. Check: `npm run verify:events -w @prism/web`; measure: `apps/server/scripts/measure-idle-clients.ts`.

## Real-time Collaboration (type-aware Hocuspocus)

`apps/server/src/collab.ts` runs a **Hocuspocus (Yjs) WebSocket** at `/collab`. It is **type-aware**: `noteKind(note)` → `document | code | spreadsheet | canvas` (by `metadata.prism_type` → tag → file extension), and `loadDocumentState`/`storeDocumentState` (plus the "already populated" guard) seed and persist the matching Yjs structure ⇄ the note's canonical content. The server self-seeds from Parachute, so a shared doc opens even with the owner offline. Per note, the live Yjs binary is cached in SQLite (`collab_docs`) for CRDT continuity; an external Parachute edit (vault `updatedAt` newer than our snapshot) wins and re-seeds.

| Kind | Yjs structure (field) | Persisted as | Client editor (`@prism/core`) |
|---|---|---|---|
| document | `XmlFragment` ("default") | HTML | `CollabEditor` (TipTap) — + comments + suggestions |
| code | `Y.Text` ("codemirror") | raw source | `CollabCodeEditor` (CodeMirror + y-codemirror.next) |
| spreadsheet | `Y.Array<Y.Array<string>>` ("rows") | CSV | `CollabSpreadsheet` (grid) |
| canvas | `Y.Map<id, element>` ("elements") | Excalidraw scene JSON | `CollabCanvas` (Excalidraw) |

Connection auth (`authorizeConnection`) resolves the same `effectiveLevel`: below `view` → reject; below **`edit`** → read-only (**suggest-only enforcement**: raw Yjs updates need edit; Hocuspocus refuses a read-only connection's `Update`/`SyncStep2` wholesale, and the client sees `provider.authorizedScope === "readonly"`). Suggest-level people and capability guests keep live reading + presence and change a prose document only through the bounded, server-authored commands at `POST /api/collab/:id/commands` (`src/human-collab.ts` + `routes/human-collab.ts`: suggested insert/delete/replace within one paragraph, comment, reply, resolve, delete-comment; server-derived identity; revision + quote checks → 409; durable SQLite receipts `collab_command_receipts`; per-actor rate (`COLLAB_COMMANDS_PER_MINUTE`, 30) and size budgets; code/sheet/canvas → 400). **Collab gotchas (learned the hard way).**
- **Restart pm2 `prism-server` after ANY server change** — it compiles via tsx on start but does NOT hot-reload. A stale server with an older `noteKind` will persist a note through the WRONG path and **corrupt it** (e.g. canvas scene JSON wrapped in `<p>`).
- **Excalidraw**: paint RAW `Y.Map` values via `updateScene`; do NOT use `restoreElements` (it silently drops valid elements when reconciling fractional indices across a set). Loop-safety: `onChange` only writes elements whose monotonic `version` increased; the map observer ignores `LOCAL`-origin transactions. `appState` (zoom/scroll) is per-viewer, not synced.
- The Y.Map (canvas) re-seeds **idempotently** (set-by-id); the Y.Array (spreadsheet) can **double** if re-seeded while a client holds rows — only happens if the SQLite docState is lost under a live client.
- Test on throwaway `_test` notes; mint an edit capability against the running DB+secret (`createCapability` + `signCapability`) to drive `/collab/:id?t=` without owner login. Bust the PWA service worker (`getRegistrations().unregister()` + `caches.delete()`) or you test stale JS.

## Content Type & Renderer Pipeline

The full chain from vault note → screen:

1. `Canvas.tsx` fetches the active tab's note via `useNote(id)`
2. `inferContentType(note)` checks (in order): `metadata.prism_type` → `metadata.type` (if in `KNOWN_TYPES`) → tag mapping in `TAG_TO_CONTENT_TYPE` → path extension → default `"document"`
3. `getRenderer(contentType)` in `Registry.ts` returns the lazy-loaded React component
4. The renderer receives `RendererProps`: `{ note, onSave, onMetadataChange }`

**Virtual tabs** (e.g. `"messages-dashboard"`, `"calendar-dashboard"`, `"agent-activity"`) never hit Parachute — `Canvas.tsx` synthesizes a fake `Note` object and bypasses `useNote()`. Their `noteId` either contains `:` (non-numeric) or is in `VIRTUAL_TAB_IDS`.

**Adding a new renderer:**
1. Create `src/components/renderers/FooRenderer.tsx` — `export default function FooRenderer({ note, onSave, onMetadataChange }: RendererProps)`
2. Add lazy import and map entry in `Registry.ts`
3. Add `"foo"` to `ContentType` union in `src/lib/types.ts`
4. Add to `KNOWN_TYPES` in `content-types.ts` and to `TAG_TO_CONTENT_TYPE` if tag-driven
5. Add to `KNOWN_TYPES` list in the Rust `enrich_note` function

### Server agent runner (`apps/server/src/agent-exec.ts`, `/api/agent/*`)

**SERVER-OWNER-only** (decision D3, "owner-only until per-actor tokens": `actor.kind === "user" && actor.role === "owner"` — an owner session or owner device token; admins/members/guests/links/anon → 403, because the run uses the VAULT token, which bypasses per-note grants and private-note rules) one-shot `claude -p` dispatches against the actor's active vault (hardened in Arch v2 WP0.1). The argv is a fixed template; the client supplies only prompt/skill/noteId. **Isolation flags** (all asserted by `test/agent-exec.test.ts`):
- `--strict-mcp-config --mcp-config <tmp>` — the ONLY MCP server is `parachute-vault` for the target vault, written per dispatch as a 0600 file in a 0700 `mkdtemp` dir and deleted when the run ends (exit, error, cancel, spawn failure). Without `--strict-mcp-config`, user-scope servers in `~/.claude.json` and the repo `.mcp.json` load too (`--mcp-config` only *adds*).
- `--tools ""` (no built-in tools at all — no Read/Write/Bash/WebFetch/WebSearch/Task) + `--allowedTools mcp__parachute-vault` + `--permission-mode dontAsk --permission-prompts none` — the vault MCP is auto-approved, everything else denied, nobody is prompted. `--dangerously-skip-permissions` is gone.
- `--setting-sources ""`, `--no-session-persistence` (one-shot only — sessions use `--session-id`/`--resume`, below), cwd = fixed EMPTY `~/.prism/agent-cwd` (`AGENT_CWD`; created 0700 lazily at first run; a **non-empty cwd refuses to run** so a planted CLAUDE.md can't become context).
- Env is an **allowlist** (`ENV_ALLOWLIST`: HOME/USER/LOGNAME/LANG/LC_*/TMPDIR/TZ + a fixed PATH + `CLAUDE_STREAM_IDLE_TIMEOUT_MS`, `DISABLE_AUTOUPDATER`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` — auto-memory would read `~/.claude/projects/<cwd-slug>/memory/`, a context source outside the checked-empty cwd; verified off via `init.memory_paths: null`). HOME is what the CLI needs to find the claude.ai subscription login. No server secret (`PARACHUTE_TOKEN`, `SESSION_SECRET`, …, nor `ANTHROPIC_API_KEY`) is ever inherited — an API-key login would need an explicit, deliberate addition.
- `resolveClaude()`: `which claude` → `~/.local/bin/claude` (native installer) → `~/.npm-global/bin/claude` → bare `claude`.

**Capacity.** Global semaphore `AGENT_MAX_CONCURRENT` (default 1) + memory admission (**macOS:** `memory_pressure` free% >= `AGENT_FREE_MIN_PCT` (15) AND kernel `kern.memorystatus_vm_pressure_level` < 2 at admission (a local skill run already in flight, model resident, tolerates `warn` and stops only at `critical` — a 7 GB model on the 16 GB mini sits at warn while inferring; 2026-10-01 runs stopped at 1/243 otherwise) AND absolute free swap >= `AGENT_SWAP_MIN_FREE_MB` (512) — the swap floor applies ONLY when the swap volume `/System/Volumes/VM` has < 4 GB free, since macOS adds swap files on demand (2026-10-01: 466 MB "free" swap with 159 GB disk free stopped classify, a false alarm) — NOT swap-% of total, since macOS grows swap on demand and % used reads 80-95% while memory is healthy; **Linux:** swap used <= 80% + free%; `AGENT_SWAP_MAX_PCT` is now an optional extra guard, honoured on any OS only if explicitly set, default unset on macOS / 80 on Linux, so a prod stopgap like 97 is harmless; refusal reasons name the metric, e.g. "memory pressure: 12% free (< 15%)" / "swap nearly exhausted: 300 MB free (< 512 MB)"; macOS probe = `sysctl vm.swapusage` + `memory_pressure -Q` — **not** `os.freemem()`, which excludes cache and always reads low; Linux = `/proc/meminfo`). Excess or memory-refused dispatches sit in status `queued` with a `queuedReason` and are re-checked every `AGENT_ADMISSION_RETRY_MS` (15 s); only a full queue (`AGENT_MAX_QUEUE`, 20) is refused (503). An unreadable probe fails OPEN (the cap still holds). `GET /api/agent/runner` reports running/queued/last verdict. `AGENT_MAX_BUDGET_USD` adds `--max-budget-usd` (default **1.00 per process/turn**; `0` disables). 30-min wall clock (SIGTERM, SIGKILL after 10 s).

**SSE** (`GET /api/agent/stream/:id`): `snapshot` (full dispatch once) → `delta` `{text}` (new output only) / `status` (metadata, no output) → `end` (metadata + `outputLength`), then closes. Never re-send the accumulated output per chunk.

**Live check:** `node --import tsx scripts/verify-agent-exec.ts --env <sandbox.env>` — requires an explicit env file (`AGENT_VERIFY_VAULT_URL/_VAULT/_TOKEN`), refuses :1940/:8787, provisions nothing, and asserts from the CLI's `system/init` (via `src/agent-init-check.ts`) that the tool list is ONLY `mcp__parachute-vault__*`, the only MCP server is `parachute-vault`, permissionMode is `dontAsk`, and cwd is the agent cwd. **One run queue.** `enqueueRun(RunSpec)` in `agent-exec.ts` is the single semaphore + memory-admission queue + 30-min clock + per-run 0600 MCP config for EVERY `claude` process — one-shot dispatches (`startDispatch`, used by `/dispatch` and the skill scheduler) and session turns compete for the same slots.

### Durable agent sessions (`apps/server/src/agent-sessions.ts`, Arch v2 WP3.1)

Multi-turn conversations a phone can start, leave and reconnect to. Tables (`db.ts`): `agent_sessions` (id = the CLI session uuid, `vault_id`, `owner_email`, `profile`, `note_id`, `cli_session_id`, `status idle|running|archived`, `transcript_note_id`, `cost_usd`), `agent_turns` (`status queued|running|done|error|cancelled|interrupted`, pid, exit_code, error, cost_usd), `agent_events` (`(session_id, seq)` PK, JSON payload). A session is visible only to its creator in the vault it was created in (other users' → 404); the router-wide SERVER-OWNER gate applies to every session route too (admin/member/guest/capability/anon → 403).

**API** (`/api/agent`): `POST /sessions {title?, noteId?, profile?: "vault-ro"|"vault-rw"}` → `{sessionId}` · `GET /sessions?limit=&archived=1` · `GET /sessions/:id` → `{session, turns[+finalText, tools, touched]}` · `POST /sessions/:id/turns {prompt, noteId?}` → `{turnId, status}` (409 while a turn is queued/running or the session is archived; 503 queue full, rolled back) · `GET /sessions/:id/stream?after=N` (SSE) · `POST /turns/:id/cancel` · `DELETE /sessions/:id` (archive: cancels an active turn, keeps the vault transcript, deletes the CLI's on-disk transcript). `/dispatch*` stays as the one-shot alias.

**Per-turn argv** = the hardened template + `--output-format stream-json --verbose --include-partial-messages` + turn 1 `--session-id <uuid>` / later `--resume <uuid>` (server-minted uuid, validated) + `--allowedTools` per profile: `vault-rw` = an EXPLICIT list `query-notes, create-note, update-note, delete-note, list-tags, find-path, vault-info, doctor, read-attachment, request-attachment-download` (never the whole server: the admin-verb tools `update-tag/delete-tag/rename-tag/merge-tags/prune-schema/manage-token` and `request-attachment-upload` stay denied); `vault-ro` = `query-notes, list-tags, find-path, vault-info, doctor` (vault 0.7.9 manifest verb `read`; `doctor` is a read-only scan that never auto-fixes). vault-ro also runs on a per-turn **READ-scoped hub token** (`parachute auth mint-token --scope vault:<v>:read`, 3 h TTL, `sub agent-session:<id>`, revoked at turn end; mint failure fails the turn CLOSED with 503; `AGENT_RO_READ_TOKEN=0` disables this second layer) (comma-joined, one argv element). Write tools still appear in `init.tools` under vault-ro, but dontAsk denies them — verified live: the call comes back as an error `tool_result` and no `note_touched` is emitted. `buildClaudeArgs` refuses any allowlist entry that isn't the vault server/its tools.

**Event schema** (`agent-events.ts` `StreamNormalizer`, stored as `agent_events.payload`): `init {cliSessionId, model, tools, mcp}` · `text_delta {blockId, text}` (**live only, never persisted**) · `text {blockId, text}` (the coalesced block; deltas with the same `blockId` concatenate to it exactly) · `tool_use {id, name, input}` (input **redacted** — secret-named keys, JWT/Bearer/`pvt_`/`sk-`/hex-key values — and truncated) · `tool_result {toolUseId, ok, summary}` (≤300-char scrubbed summary, never raw output) · `note_touched {noteId, op}` (from a SUCCESSFUL `create/update/delete-note` result only) · `status {status, reason?}` · `result {ok, costUsd?, durationMs, numTurns?, error?}`. SSE: persisted events are `id: <seq>` / `event: <t>` / `data: {seq, turnId, …event}`; deltas are `event: text_delta` with **no id** (so `Last-Event-ID` only ever points at persisted seqs). Replay = seq > max(`?after`, `Last-Event-ID`), subscribe-before-replay with seq dedupe, then live until the turn's terminal `status`; with nothing in flight it closes after the replay. `: ping` every 25 s.

**Lifecycle.** Open-note content goes into the FIRST turn only (≤8000 chars, fenced as data); later turns get at most `Active note: <id>`. `index.ts` runs `bootSweepAgentSessions()` before serving: queued/running turns → `interrupted` (+ a persisted status event), sessions → `idle`. On every turn end the whole session re-renders into ONE vault note `vault/agent/sessions/<created-date>/<slug>-<id8>` (tags `agent-session` + `agent-dispatch`, metadata in the AgentActivity dispatch shape + `sessionId/profile/turns/costUsd`), holding prompts, final replies, tool NAMES and touched ids — never tool inputs/results. The note is **private to the session owner** (`metadata.prism_creator` = owner email, `prism_visibility: "private"`). Written to the session's own vault (`vaultClient(vault_id)`), best-effort; `AGENT_TRANSCRIPT_MIRROR=0` turns mirroring off. Never re-rendered for an archived session.

**Guards + retention.** Open-note context needs `effectiveCaps(...).has("view")` for the requesting actor (someone else's private note → 403, turn rolled back); internal callers with no actor never inline note content. `AGENT_SESSION_BUDGET_USD` (default 10; ≤0 off) refuses new turns once the session's cumulative `cost_usd` reaches it (409 `budget_exceeded`). **One active turn per user across sessions**: further turns wait FIFO as `queued` ("waiting for your other agent turn to finish") and start when the slot frees (the per-session rule stays a 409). `text`/`text_delta` pass through `scrubSecrets` (a token split across deltas is only caught in the final `text`). **Archive** cancels an active turn, deletes the CLI's `<id>.jsonl` AND sidecar dir `<id>/` (tool-results), and deletes the session's `agent_turns` + `agent_events` rows (the session row + transcript note stay); a child that outlives the archive purges again in its onEnd. `startAgentMaintenance()` (boot + daily): prunes events older than `AGENT_EVENTS_RETENTION_DAYS` (30) for live sessions, wipes rows left on archived sessions, and deletes uuid-named CLI artifacts under the agent-cwd project dir older than `AGENT_CLI_RETENTION_DAYS` (14) that don't belong to a non-archived session (non-uuid names like `memory/` are never touched). `seq` comes from `agent_sessions.event_seq` (a counter), so pruning never reuses a seq. `cliSessionFile`/`cliSessionSidecar` refuse non-uuid ids before any fs op.

**Session gotchas (verified against CLI 2.1.x, stub MCP).**
- **The CLI does NOT write into the cwd.** It persists the conversation at `$HOME/.claude/projects/<slug>/<uuid>.jsonl`, slug = `realpath(cwd)` with every non-alphanumeric → `-` (`cliSessionFile()`). The cwd stays empty across turns, so the WP0.1 emptiness guard is unchanged — but `--resume` finds the session **by cwd slug**, so every turn must run from the same fixed cwd (changing `AGENT_CWD` orphans existing sessions). That file (and a `<uuid>/` sidecar dir for large tool results) holds raw tool results (vault content), 0600; archive deletes both.
- `--session-id <id>` on an id the CLI already has fails ("Session ID … is already in use"); `--resume` of an unknown id fails ("No conversation found", `error_during_execution`, $0). So turn N resumes iff `cli_session_id` was recorded OR `cliSessionFile` exists (a turn 1 that died after the CLI wrote its file).
- `result.total_cost_usd` is **cumulative across `--resume`**; per-turn cost = delta vs `agent_sessions.cost_usd`. `--max-budget-usd` (`AGENT_MAX_BUDGET_USD`) is **per process/turn**, not per session — verified: a resume with a cap BELOW the already-accumulated session total still ran and succeeded. The session-level cap is therefore enforced server-side (`AGENT_SESSION_BUDGET_USD`).
- Fixtures `test/fixtures/agent-stream-*.jsonl` are real CLI output with host-specific init fields (skills, plugins, memory paths, sockets) and thinking signatures stripped — re-record the same way if the CLI's stream shape changes.

## Prism MCP (`/mcp`, Architecture v2 WP6.1)

The Prism Server serves its OWN MCP endpoint — distinct from the vault MCP above. It acts as the caller's **Prism account** (per-note grants, private notes, caps), so it is the safe way to give member agents access. User doc: `docs/mcp-access.md`.

- **Transport:** stateless Streamable HTTP, MCP 2026-07-28 (`@modelcontextprotocol/server` 2.x `createMcpHandler`, a fresh `McpServer` per request; 2025-era `initialize` clients served by the SDK's stateless fallback). Code in `apps/server/src/mcp/`: `router.ts` (`mountPrismMcp(app, mountPath)` — also mountable at `/surface/prism/api/mcp`; RFC 9728 metadata at `/.well-known/oauth-protected-resource<mount>`, Origin check, rate limits, 401 `WWW-Authenticate: Bearer resource_metadata=…`), `auth.ts` (bearer → `McpPrincipal`), `tools.ts` (registry), `dispatch.ts`, `errors.ts`, `tool-whoami.ts`.
- **Auth (bearer only — session cookies and capability links are NEVER accepted on /mcp):** `pp_` Prism PATs (table `mcp_pats`, `auth/pat.ts`; SHA-256 only, bound to ONE vault, `read|write` ceiling, 1–365 d; managed at `/auth/pats` via `routes/pats.ts` + Settings → Account → "Agent access tokens"); `pd_` device tokens; the owner's hub JWT — **OPT-IN** (off unless `MCP_OWNER_HUB_SUBS` is set; then it needs `vault:<primary>:admin` scope **AND** an exactly-allowlisted `sub`; member-minted `mcp:*`/`mcp_tokens` JWTs and `scoped_tags` tokens refused; verifier injectable via `setHubJwtVerifier`); `COLLAB_TOKEN` loopback-only. **A PAT is recognised only by `/mcp`** — `resolveActor()` doesn't know it, so it is never a web credential. Revoking a device revokes PATs minted through it.
- **Tools:** `defineTool({name, scope: "read"|"write" REQUIRED, description, inputSchema (zod/v4), annotations: {readOnlyHint REQUIRED, must agree with scope — else defineTool throws}, access REQUIRED, handler})`. `tools/list` = only tools whose `access(principal)` is true (read-only credentials additionally see only read-scope tools, and a write-scope tool is refused at CALL time too); `access(principal, args)` is re-checked per call; a hidden tool answers exactly like a nonexistent one. Handlers return JSON or throw `ToolError`; `mapToolError` maps everything else (vault errors like `vaultErr`; unknown → `internal_error`, logged, never echoed). One audit line per call, no args. Add tools to `PRISM_TOOLS` in `router.ts`.
- **Tools reach data through the gateway, not around it:** `ctx.dispatch(path, init)` runs a Prism route IN-PROCESS as the principal's actor (`app.request(..., env)` with the actor under the module-private `INPROCESS_ACTOR` symbol that `resolveActor` honours first; cookie/authorization stripped, `X-Prism-Vault` pinned). Only Yjs tools (WP6.3) need direct code.

## Version history (Parachute vault ≥ 0.7.9)

The vault captures the prior content + metadata of a note on every update, append, delete and restore (20-version floor, 100 ceiling, 180 days, 8 MiB/note; per-vault `history:` block in `vault.yaml`, read at vault start). Prism surfaces it everywhere through the `VaultClient` seam — `listNoteVersions` / `getNoteVersion` / `restoreNoteVersion` (optional methods; `HistoryUnavailableError` on a 0.6.x vault, whose `/versions` 404s even for an existing note) — implemented by `HttpVaultClient` (gateway) and `TauriVaultClient` (Rust `vault_list_note_versions` / `vault_get_note_version` / `vault_restore_note_version`).

- **UI:** `components/layout/HistoryPanel.tsx` (context-panel History tab; also the "Version History" command and the mobile More sheet) — current version + day-grouped timeline, size deltas, paging. `components/history/VersionViewer.tsx` (portaled to `<body>`) — diff vs the current note ("what restoring does") or vs the version before ("what that save changed"), full text, ←/→ stepping, two-step Restore. Diffs come from `lib/history/diff.ts` (HTML → paragraphs, Excalidraw scene → element list, word-level edits, folded context).
- **Semantics:** a version row is the state *before* a change; `supersededAt`/`op` describe the change that replaced it, so a row's "saved at" is the NEXT-OLDER row's `supersededAt`. Restore brings back content + metadata only (tags and path stay), needs the reviewed `if_updated_at` (the vault refuses `force`), and captures the replaced state — every restore is undoable.
- **Restore safety (`useRestoreVersion`):** flush pending autosaves first (`flushPendingSaves` — the user's typing becomes a version, never lost) → restore against the post-flush `updatedAt` → `discardPendingSaves` → `bumpNoteRevision` so `Canvas` remounts plain renderers on the new content. Live collab docs keep their session: the server reconciler folds the restore in within ~2 s.
- **Collab gotcha:** `storeDocumentState` skips the vault write when the serialized doc equals the note's content — otherwise every fold/idle store would add a no-change history version.
- **Compaction:** the vault only compacts at open or via admin `POST /api/history/compact`; `worker/history-compact.ts` runs it daily per vault in short slices with an ephemeral admin token (`HISTORY_COMPACT_INTERVAL_MS`, 0 = off).
- **2 MB ceiling:** a note over 2,000,000 bytes cannot be updated while history is on — hence Matrix thread rollover. Upgrade plan + research: `docs/roadmap/parachute-upgrade/`.

## Shell, sync state, search and offline polish (wave 2E)

- **One truthful sync state** (`packages/core/src/lib/sync/syncState.ts`, `SyncStateBadge`). `Shell` re-provides the VaultClient wrapped by `trackVaultWrites` (memoised Proxy; only write methods are wrapped): a write counts as in flight until it settles AND `hasPendingWrites()` has been re-read, so an outbox-queued write never reads "Saved". Other inputs: `useAutoSave` (`markDirty` while debounced, `reportSaveFailure` with its own `saveNow` retry — **a 409/428 is never retryable: the draft goes to the outbox as a `conflict` row via `preserveDraft(…, "conflict")` → "Needs review"**), the web `OfflineIndicator` (`reportPendingWrites(count, needsReview)`; listens for `prism:open-saved-changes`; toasts `prism:offline-refused`), live collab docs (`reportSyncSource`; socket down with unsynced edits = `local`, never "Saved"). `deriveSyncStatus` order: failed → review → offline/local → saving → waiting → saved. Don't revert it.
- **Offline writes (`apps/web/src/offline/outbox.ts` + `rest.ts` `writeJson`) — what queues, what retries, what refuses.**
  - **Queued offline and retried automatically** (backoff 1.5 s → 60 s) when the server gives no answer / 5xx / 429 — rows for which a duplicate delivery is harmless (`retrySafe`): content saves WITH a base revision (coalesced per note into one row: first base, latest content), metadata merges without a base (`kind: "meta"`: properties, icon, font — coalesced; each key keeps its PRE-EDIT value in `expect` and replays per key through `POST /api/properties/:id {set, expect}`, or read + CAS PATCH for `prism_*`/older servers; a key changed elsewhere → review naming the keys), tag/link deltas, and creates (every create carries `metadata.prism_client_op`; after an unconfirmed outcome or a 409 the outbox looks the path up and ADOPTS its own page, else review with "Retry" / "Create under another name"). A replay 409 whose content/values are already on the server is success (lost acknowledgement).
  - **Kept for review, never re-sent blindly:** a content save with no base revision; any row that hit a real conflict (409), a missing page (404/410) or lost access (401/403).
  - **Refused — an error + toast, nothing queued, never an optimistic success — offline AND when the server is unreachable/5xx:** rename/move (`path`; with unsent rows for the page it flushes first, else refuses), delete, nested metadata values (`prism_database`, dashboard `layout`, board config: one object to the vault), every pages route (move/trash/restore/lock/order/style), version restore, everything else.
  - **Invariants (do not break):** `flush()` re-reads each row, `claim()`s it, resolves references FROM THE CLAIMED ROW and sends only that body; `confirm()` deletes a row only if it still holds what was sent (an edit folded in during a flush pass used to be dropped under a "Saved" badge). A `sending` row is never folded into. Every confirmed delivery re-bases later queued saves made on the revision it replaced, records it in the per-tab `superseded` map (shared over `BroadcastChannel("prism-outbox")`, read by `currentBase()`), and fires `prism:note-confirmed` (Shell re-reads the page). A stuck or waiting row holds back only LATER rows of the SAME note. `localNote` overlays only rows that will be sent (`queued`/`sending`) and MERGES metadata. Discarding a stuck row sends later rows of that note to review. Queued creates are part of `listTree` (unique paths). A dead sender's `sending` row returns to the queue after 35 s if retry-safe. Rows never replay under another account/vault (`sameScope`); rows of other scopes are counted in the dialog and purged after 30 days; `logout()` asks Stay / Download / Discard when unsent rows exist; an IndexedDB write failure raises `prism:storage-failed` (standing banner). Rows are plaintext in IndexedDB.
  - Specs: `notion-outbox.spec.ts`, `notion-offline-writes.spec.ts`, `outbox.spec.ts` (fixture enforces CAS; `window.prismShell.failures/holdIds/unreachable`).

## Bioregional Knowledge Commons (governance + geospatial)

Prism can run as a governed, geospatial wiki for a bioregion. Status, verification battery (P0–P4 test counts), and the readiness audit + what it resolved live in `docs/roadmap/bioregional-commons-PROGRESS.md` (see "2026-09 Commons Charter"). The two plans `bioregional-commons-1-governance.md` / `-2-graph.md` are the ORIGINAL research/design docs (v0) — the powers vocabulary they describe (`review`, `certify_gardener`, `arbitrate`) was superseded during implementation; treat them as history, not reference. **The operator/member guide is `docs/governance.md`.**

**Governance is note-native and a parallel subsystem — that bridges into ordinary content grants.** State (config, roles, policies, memberships, proposals, votes, revisions, audit) is stored as `governance-*` tagged vault notes. Layers: pure engine `apps/server/src/governance.ts` → store seam `governance-store.ts` (notes ⇄ structures) → service `governance-service.ts` (`mutateGovernance` is the single choke point) → grants bridge `governance-grants.ts` → routes `routes/governance.ts` (`/api/governance`, mounted before the gateway). UI is `packages/core/.../network/governance/*` (`BootstrapWizard`, `RoleEditor`, `PolicyBuilder`, `ProposalsPanel`, `YourAccess`, …), surfaced as **Network → Governance** (the standalone `/governance` route is dev-only).
- **Capability vocabulary (P1).** Content access is `Cap` = `view | comment | suggest | edit | create | organize | delete | share` (`permissions.ts` `CAPS`) — a composable sibling to the `Level` ladder (`view<comment<suggest<edit<own`). A grant's `caps` column is nullable: `null` means "derive from level" via `expandLevel` (nested sets, so every pre-caps grant behaves byte-identically); an explicit list is authoritative and the stored `level` is kept coherent by `levelForCaps` — the highest level whose full expansion is *contained in* the caps, so a caps grant can never INFLATE what a level-only consumer sees (a `create`-only drop-box grant floors at `view` on the ladder but `effectiveCaps` correctly reads it as no view access). `effectiveCaps` mirrors `effectiveLevel`'s matching + private-note semantics exactly. **Every READ gate asks `effectiveCaps(...).has("view")`, never `atLeast(effectiveLevel(...), "view")`** — the ladder floor leaks caps grants like `["create"]` (gateway, semantic search `routes/rag.ts`, publish `canPublicView`, collab socket, federation peer bridging all do; WP0.2). `effectiveLevel` survives only for `_level` display and the collab socket's level projection.
- **THE BRIDGE (P2) — this is how governance gates content, and the ONLY way it does.** While `config.enabled`, `governance-grants.ts` `compileGovernanceGrants` turns active memberships × role `capabilities` into ordinary grant rows: a tag-scoped role → a `tag` grant, a global role → a `vault` grant, `created_by: "governance:<roleId>"`, overlapping roles' caps UNIONED, expiry taken from the membership (`null`/never beats any date). `reconcileGovernanceGrants` diffs against ONLY rows it owns (`created_by` starts `governance:`) and converges by delete+insert — a hand-made grant at the same (subject, resource) is never touched. Disabling governance compiles to the empty set, which is exactly how disable revokes everything it granted. Runs after every successful governance mutation (best-effort, `routes/governance.ts` `reconcileGrants`) AND on a worker tick every `GOVERNANCE_RECONCILE_MS` (default 300000 = 5 min; a cached "does a constitution exist" probe keeps an unconfigured vault to one query per interval). `effectiveCaps`/`effectiveLevel` (`permissions.ts`) remain the ONLY content guard — `routes/api.ts`, `collab.ts`, and `routes/acl.ts` never call into governance; governance only ever WRITES grants for them to read. (Supersedes the old "governance does not gate content" claim — it gates content exclusively, and only, by writing grants.)
- **POWERS, made honest (P2).** `publish | assign_roles | manage_policy | invite | revoke | amend_governance` (`governance.ts` `POWERS`). `review` and `arbitrate` were cut (redundant / never built); `certify_gardener` → `assign_roles`. `parseRole` drops unknown power names, so a note written under the old vocabulary degrades silently instead of failing to load. Only `publish` (`routes/governance.ts` publish route) and `assign_roles` (delegated staffing, below) are enforced today; the rest are declarative. **Delegated staffing:** post-lock, a role holding `assign_roles` may add/remove memberships of any role its `assigns` list names — no proposal, scope-compatible only (global assigner, or same-tag) — audited as `delegated:*`. `canDelegateMembership` refuses this for ANY role carrying `amend_governance`: constitutional power changes hands only through amendment, never delegation.
- **The bootstrap lock is a one-way latch — and it now has a pre-flight.** Before *Enable & lock*, only the bootstrap owner may configure directly; after, `canMutateGovernanceDirectly` is false for everyone (including the owner) and every change — including disabling — needs an approved `amend_governance` proposal through `mutateGovernance`. Do not add a bypass. `validateRatification` (P0) refuses to lock a constitution that could not pass its own amend policy (missing policy/role, or fewer active eligible members than the threshold) — the un-amendable-forever landmine is closed at the point of locking, not after. `mergeConfig` (P0) protects `bootstrapOwner` (always) and `amendPolicy` (while staying enabled) from being blanked by a partial `set_config` — the old disable-template brick is closed. Recovery from a bricked constitution is still: delete the `governance-config` note with the owner Bearer over loopback.
- **Full CRUD lifecycle + idempotent upserts (P0).** `GovChange` has 9 kinds — `set_config`, `add/update/remove_role`, `add/update/remove_policy`, `add_membership`, `remove_membership` — each effected in `governance-service.ts` `effect()`. Adds are UPSERTS keyed by natural identity (role name; policy action+scopeType+scope; membership subject+role), so re-running `commons-init` CONVERGES instead of duplicating. `remove_role` cascades to its memberships; removing/retargeting the amend policy is refused outright (governance can never be made un-amendable by amendment). Pre-lock, the same choke point is reachable via PATCH/DELETE fixup routes on `/api/governance/roles|policies` and `DELETE /memberships` — post-lock they 403 into `requires_proposal` like everything else.
- **Votes are mutable; windows auto-close (P0).** A voter may revise their sign-off while a proposal is open (`upsertVote`, one note per (proposal, voter)). A policy's `windowSeconds` auto-closes an expired open proposal to `rejected` on the next vote/apply touch (`proposalWindowExpired`); approvals that landed in-window still apply late even after the window closes.
- **Scoped share (P2).** A non-admin holding the `share` cap on a note or tag reaches exactly five ACL routes — `PUT`/`DELETE .../people` for note and tag, plus `GET /notes/:id` — matched in `routes/acl.ts` `SHARE_ROUTES`; everything else on `/acl` stays admin-only. Anti-escalation: the caps handed out must be a SUBSET of the sharer's own (`denyEscalation`), and only to people who already have an account (auto-inviting a stranger is still admin-only).
- **The wiki loop (P4).** The gateway stamps non-owner, signed-in reads with `_caps` (`routes/api.ts` `annotate` / `GET /notes/:id`) — never for the owner passthrough, never for a capability link (the affordance needs a session). `reviewMode(note._caps)` (`packages/core/src/lib/governance/review.ts`) is the one gate every P4 affordance reads: no `_caps`, or `_caps` includes `edit` → `"none"` (behaves exactly as before P4); `suggest`/`create` without `edit` → `"propose"` (local-editable draft, "Submit for review" → `POST /api/governance/content/propose`, an `edit_note` proposal); else `"read-only"`. Canvas routes propose-only notes away from the live collab session — their keystrokes have no right to land in the shared Yjs doc. `notifyVoters` (`governance-notify.ts`) fires on every proposal open: pure `eligibleVoters` (scope-aware, proposer excluded) addressed via the SAME `sendEmail` plumbing as magic links (Resend when configured, console line otherwise), capped at 50 recipients, every failure swallowed — fire-and-forget, never blocks the proposal response.
- **Constitution prose.** `packages/core/src/lib/governance/prose.ts` `renderConstitution` regenerates the `governance-config` note's CONTENT (never its metadata) after every successful governance mutation (`writeConstitutionProse`, best-effort, alongside the grants reconcile). **Hand-edits to that note's body are silently overwritten on the next change.** Role/policy notes get one-line prose bodies (`renderRoleSentence`/`renderPolicySentence`) on add and update too.
- **Don't admin-gate the Governance tab.** Members vote on proposals; the handler is member-authed. In `NetworkRenderer.tsx` `canGovern` is intentionally not `&& isAdmin`.
- **Governance integrity (WP0.3) — governance notes are SIGNED, and unsigned ones are ignored.** With `GOVERNANCE_SIGNING_SECRET` set, every governance note the service writes carries `metadata.gov_sig` = `v1.` + HMAC-SHA256 over `{tag, note id, authority projection}` (`governance-integrity.ts`); the projection is every metadata key the matching `parse*` reads, coerced through the SAME helpers (`governance-fields.ts` — parsers must never read a key the projection doesn't cover), plus a content SHA-256 for **revisions only** (their content is what gets published). Config/role/policy prose is NOT signed (regenerated by `writeConstitutionProse`). Every loader (`loadState`, `loadVotesFor`, `listAudit`, `listRevisionsFor`) and every service lookup (`govNotes`, `getProposal*`, `revisionForProposal`, publish/rollback) filters through `verifiedGovNotes`/`verifyGovNote`: missing/invalid sig → excluded + one `[governance] INTEGRITY:` warn per note id. **Anti-replay ledger:** the sig must ALSO equal the note's current sig in SQLite `governance_sig_ledger(vault_id, note_id, sig)` (db.ts, keyed `"primary"`) — every signed write upserts it, every governance delete (`deleteGovNote`) writes a tombstone (sig NULL, written even with integrity off); no row → untrusted (no TOFU), tombstone → untrusted. This is what stops a vault `/restore` of an older signed state (re-opening an applied proposal, wider caps) or recreating a deleted note with its old id+sig. **Consequence: `prism-server.db` now carries governance trust** — losing it or restoring an older copy makes governance vanish or partly revert until `governance-sign-existing.ts` is re-run (it rebuilds missing rows without rewriting notes; valid-but-not-current sigs are `skip-mismatch` for review, tombstoned recreations are never blessed). Restore vault + server DB together; `scripts/backup-parachute.sh` already snapshots the whole DB. **All service writes/deletes go through `createGovNote`/`updateGovNote`/`deleteGovNote`** — never call `vault.createNote/updateNote/deleteNote` on a governance note directly (create is two writes with the secret on: the sig binds the vault-assigned id, so a copy never verifies). `updateGovNote` refuses to re-sign a note that doesn't verify (no laundering). No secret → byte-for-byte the old behaviour + one startup warning. Turning it on REQUIRES `scripts/governance-sign-existing.ts --env <file> [--apply]` (dry-run default, no default env file, idempotent) or the whole constitution vanishes. Tests seeding governance via `fv.put` only work with integrity off (the default in `.env.test`). **Residual risks** (docs/governance.md): a vault-write token can still DELETE governance notes (DoS / fall back to the default policy — never a grant); a crash between the vault write and the ledger write leaves that one note untrusted (fail-closed) until rewritten or migrated.
- **Member whole-vault MCP tokens are frozen (WP0.3).** `POST /api/mcp/token` → 403 `minting_disabled` unless `MEMBER_VAULT_TOKENS=true`; `GET /api/mcp` reports `mintEnabled`/`mintDisabledReason`; list + revoke keep working for cleanup. Prism MCP credentials (WP6) replace them. There is no mint UI (API-only).
- **Owner check is `actor.role === "owner"`**, not `isOwner` — main's `Actor` is a discriminated union where every kind carries `role`.
- **Gotchas.** Desktop and the web owner passthrough carry NO `_caps` ever — every P4 review affordance is provably inert on both paths, not just policy-inert (the annotation never reaches them). e2e gate: `E2E_FAKE_VAULT=1 ./scripts/e2e-governance.sh` — runs `governance.spec.ts` (bootstrap→lock→self-amend→governed content change; a contributor proposes from the editor and a steward reviews it live; the stranger-gate) plus `bioregion.spec.ts` and `import.spec.ts`, **6/6** as of the P4 contributor-loop test. Server tests ONLY via `npm test` — raw `node --test` has wiped the live ACL DB before, and governance shares that DB.

**Ontology + geometry.** `tag-schemas.json` carries the 11 bioregional types; `ecological-entity`/`species`/`watershed`/`place`/`signal` map to `contentType: "bioregion-entity"` → `BioregionEntityRenderer`. One convention: GeoJSON RFC 7946, WGS84, `[lon, lat]`, derived `bbox` (`packages/core/src/lib/geo/geojson.ts`, tested). The geometry *field name varies by type* — `geometry` (entity/place), `boundaryGeometry` (watershed), `rangeGeometry` (species); readers check all three in that order. `bbox` is stamped everywhere but nothing queries it yet.

**The Map is a virtual tab, not a route.** `MapRenderer.tsx` is registered as `"map"` (Registry + `VIRTUAL_TAB_IDS` in `Canvas.tsx` + `VIRTUAL_TABS` in `Navigation.tsx`); sidebar → Map. It loads geo-bearing notes through the `VaultClient` seam (desktop + web alike), so never fetch the gateway directly from it. `CommonsMap.tsx` is the shared MapLibre surface (OpenFreeMap vector basemap, blank fallback); `map/draw.ts` `DrawController` handles point/line/polygon → `buildGeometry` → `metadata.geometry` via `onMetadataChange`. `/map` and `/bioregion` are deep-link aliases that boot the app into the tab via `App`'s `initialTab` prop — do not resurrect a standalone panel. **The headless runner has no WebGL:** `hasWebGL()` probes up front and sets `data-map-fallback`; e2e asserts `data-map-ready` *or* `data-map-fallback`, so tile rendering and drawing need a real browser to verify.

**Importers + provisioning.** Pure transforms in `apps/server/src/importers/transform.ts` (`gbif-species`, `geojson-entities`, `wbd-watersheds`; fixture-tested). CLIs: `scripts/import-bioregion.mjs` (one source) and `scripts/commons-init.mjs --config` (schema + governance + ingest + verify; `docs/commons-provisioning.md`). Gotchas: **no idempotency** (re-import duplicates notes); opts are ignored for `gbif-species`/`wbd-watersheds`; GBIF species get no geometry so won't show on the Map; the `commons-init` verify step queries `?tag=` on the owner passthrough, which ignores it (vacuous); `commons-init` imports a `.ts` from `.mjs` so it needs Node ≥22.18. There is **no bioregion parameter** (no bbox/HUC) — the caller supplies the data file.
