# Omni nudges

The owner queue now stores one nudge per source note in SQLite, separate from vault history. The source ID is checked against the owner vault and the source link is generated by the server. Candidate text is capped; the authenticated queue supplies it to the app. APNs carries only IDs, generic text and an Omni deep link, using the dedicated Omni app topic from the native push checkpoint. Hooks can propose/resolve verified sources, report calendar busy state and persist count-only weekly audits; they cannot dismiss, start private work, approve or execute an outward action.

The Needs You screen combines drafts and nudges, with source links, Draft reply, Start working, Snooze, Not important, and a Later list. Draft reply and Start working create/reuse a source-bound Hermes thread. The prompt forbids sending or publishing; outward actions still use existing digest-bound human approval. Retry keys survive ambiguous network failures within the view model and are persisted by the server turn ledger. Off and Pause stop notifications while leaving the queue accessible.

## Interrupt controls

- Denver quiet hours are 21:00–07:00. Only an explicit urgent message less than an hour old from a top-band person can clear that hold.
- Calendar evidence expires after five minutes. Unknown, failed or truncated calendar reads hold notifications; a two-minute producer context check is required for delivery.
- A current external meeting holds everything except score ≥0.85 with an explicit deadline today.
- Normal items enter digest windows at 09:00,11:00,13:00,15:00,17:00, with a five-minute timer window and one persisted grouped notification per owner/date/hour slot. Each item claims its surface atomically; the batch consumes one hourly interruption slot. Dials cap pushes at1/2/4 per hour and score thresholds0.60/0.50/0.40. Known high-priority people have a digest floor.
- A SQLite claim reserves the surface BEFORE transport. At most two interrupt attempts per source, at least four hours apart; even an uncertain APNs response cannot produce an unlimited retry. Delivery claims/outcomes persist across restart. This is a conservative attempt budget, not proof that the person saw a notification.
- The current native app does not read the name of a Focus. Unknown Focus uses Apple's ordinary `active` notification level, which [does not break through system controls](https://developer.apple.com/documentation/usernotifications/unnotificationinterruptionlevel/active). No time-sensitive/critical bypass is requested. When an authorized client can report Work Focus, fresh Work evidence holds pushes. Work-specific batching without such evidence is not claimed. The settings screen states this limitation.

## API

All app routes require the Omni owner session/device plus the existing JSON/CSRF checks. Mutation requests downgraded to agent origin are refused.

| Route | Meaning |
| --- | --- |
| GET `/api/omni/nudges[?later=1]` | Bounded current/Later queue |
| GET `/api/omni/nudges/audit` | Latest owner-only count report |
| GET/PATCH `/api/omni/nudges/settings` | `{dial,killed}` |
| POST `/api/omni/nudges/:id/action` | `{action:noise\|relevant\|dismiss\|snooze\|seen,until?:epochMs}` |
| POST `/api/omni/nudges/:id/start` | Human `{action:draft-reply\|start-working}` plus Idempotency-Key; `{threadId,turnId}` |
| POST `/api/omni/nudges/context` | Device `{focus:none\|work\|unknown}` when actually known |
| POST `/api/omni/hooks/nudges` | Loopback service-token proposal: bounded text, source ID, score/priority, deadline/urgent timestamps, commitment flag |
| POST `/api/omni/hooks/nudges/context` | Loopback service-token `{inMeeting:boolean}` from successful calendar evidence |

Complete source evidence resolves deleted, replied and completed sources out of both queues and prevents delivery/private starts. Failed or partial snapshots never resolve sources. The audit includes verified email and Matrix replies and explicitly reports unknown chat coverage. Weekly caught counts require a view or successful delivery after inbound and before the relevant reply; later views and failed transports count as missed.

Noise feedback lowers future sender/source scores; sender identity uses canonical note IDs. Created/updated items fan out an ID-only SSE notice. Today includes the same current queue.

## Validation and release boundary

Focused policy/ledger/routes/delivery fixtures use synthetic databases, a stub Hermes and a fake APNs transport. Native fixtures cover queue settings and ambiguous-start retry. No test sends Apple pushes, reads real OAuth values or writes the production vault. The merged native APNs stage is incorporated from main.

The companion agent stage adds `omni_cli sweep-owed`: tag-independent owed replies, distinct unprocessed items, owner tasks/written commitments, T−15 real meeting-prep sources, sanitized failed-job status, freshness alerts and a complete-evidence weekly reply audit. Inventory is bounded and lean; chat sender/reply authority uses immutable Matrix event metadata, never transcript text or display names. Dry runs print counts only, and never mark mail read/triaged/relayed. Committed operational alerts create gateway-only entries with fixed job/freshness namespaces and native Recurring/status links; no vault note is created or changed. hooks never execute outward actions. The existing agent `docs/omni/row10-runbook.md` contains named no-agent schedules, their copied script wrappers, rollback, and approved-email-only activation. Coordinator installation and the one-week side-by-side observational gate remain release steps; this PR performs neither production delivery nor schedule installation.
