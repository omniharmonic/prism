## How work is admitted and closed

Every change must name a row below, its original source requirement, the observed gap, files owned, and acceptance journey. An attractive idea without that mapping is a proposal, not work to implement silently. A new user clarification is labeled as such rather than attributed retrospectively to the old plan.

Each row has **two independent gates**: behavior and visual/interaction fidelity. A route existing, a screenshot fitting the viewport, or a test count is insufficient to mark the whole row done. “Present” below means code exists; “recorded” points to earlier evidence; “audit open” means this reconciliation has not established the complete result. No row in this new matrix is being marked fully accepted yet.

For each completed slice attach: source commit; fixture scenario and viewport/theme; actual screenshot path; visual comparison against the named board; focused behavior results; remaining limitations; deployed web/native IDs and actual production checks when applicable. Use fictional fixture screenshots for reviewable artifacts. Keep private production captures out of git.
